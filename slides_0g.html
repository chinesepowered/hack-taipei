01 · 做了什麼 / 解決什麼問題

AI 幫長輩擋詐騙。但家人憑什麼相信 AI？

問題

台灣一年詐騙財損逾 500 億。阿嬤被催促的那一刻，身邊沒有人踩煞車。AI 可以判斷，可是它的判斷是一個中心化 API 的回傳值：家人看不到、驗不了，通話內容還躺在別人的伺服器上。

做了什麼

語音守護代理人「豆豆」陪阿嬤聽電話，評估風險；錢放在鏈上守護合約，可疑付款交給兩位家人共簽。今天：豆豆有 0G Agentic ID，每次判斷在 TEE 裡完成、簽成一枚章，家人與合約見章才放款。

為什麼是 Web3

「拒絕」必須是阿嬤和 AI 都改不掉的規則。放在 prompt 裡可以被說服，放在合約裡不行。而信任一個 agent 的判斷，需要它有身分、有證明、可稽核。

02 · 架構

四個 0G 元件，各做一件事

阿嬤的手機瀏覽器開麥克風。豆豆（OpenAI Realtime 語音）聽阿嬤和來電者。金額由程式碼從原話判讀，不靠模型算。
→
0G Compute詐騙防護盾跑在 0G Compute Network 的 TeeML provider。豆豆的錢包付算力，回應簽章由 SDK 驗證 → tee_verified。
→
0G Agentic ID豆豆 = 官方 AgenticID #384（ERC-8004）。每次判斷簽成一枚章：agent、模型、輸入雜湊、輸出雜湊、TEE、分數。離線可驗。
→
0G ChainGuardedWallet 在 Galileo：白名單、每日額度、2-of-2 家人共簽。提案 memo 帶 proof:0x…，一位家人就能擋。
0G Storage：每一枚章的 JSON 上傳到 0G Storage，rootHash 掛在提案上，任何人可下載重驗。
03 · WHY BUILD ON 0G

因為證明要活在 agent 之間，不能活在我們的伺服器裡

0G 元件我們怎麼用狀態
Compute防護盾推理走 0G Compute Network（broker SDK，TeeML provider，回應簽章驗證）；mainnet Router + 0GM 模型一個 env 切換live
Agentic ID豆豆 = 官方 AgenticID #384（attestor 註冊、ack trust roots、mint-only）；章綁定 ID，驗證器比對 ownerOf(384)live
ChainGuardedWallet、測試 USDC、AgenticID 對照合約全部在 Galileo；自家 /tx 頁直接讀 RPC 解碼事件live
Storage章的 JSON 上傳 0G Storage，rootHash 掛在提案 metadata，離線重驗live
拒絕不是寫在提示詞裡，是寫在合約裡。信任不是寫在文件裡，是寫在章裡。
04 · DEMO 完成了什麼（現場）

三步，全部真的

1 · 判斷

詐騙電話 → 風險條衝紅 → 「推理在 0G 隔離環境完成 · TEE 已驗證」。金額「十萬」由程式碼讀成 100,000，不是模型猜的。

2 · 章

家人頁面一秒內出現卡片（送上鏈中…），區塊落地後顯示「這個判斷有章」。按「離線驗證」：簽章有效 ✓、鏈上身分 = Agentic ID #384 ✓。

3 · 見章放款

媽媽擋下 → 鏈上 ProposalRejected，阿嬤頁面立刻通知、收支紀錄更新。關掉 Wi-Fi 也能驗那枚章。

加分項：可驗證推理（TEE 簽章驗證）· 兩個模型協作（Realtime 語音 + 0G 上的防護盾）· agent 對人的 A2H 共簽 · 14 個自動化測試
